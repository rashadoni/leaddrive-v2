## Остаточные замечания

### I-01 · P1 · Production inventory недоступен

Миграция добавляет tenant-aware ссылки, уникальность task-зеркала и exclusion
для подтверждённых интервалов. Конфликт старых данных должен остановить gate,
а не привести к автоматическому удалению или переносу встреч.

Read-only aggregate preflight подготовлен по установленному инспектору,
но зарегистрированный `leaddrive-prod` (`13.140.132.245`) отклонил SSH identity:
`Permission denied (publickey)`. Чужие ключи и retired routes не использовались.
Фактические количество старых конфликтов и совместимость production-данных
**не подтверждены**. Требуется восстановить штатный read-only доступ и выполнить
сверку до применения миграции. Это операционный release gate, не повод менять
ограничения миграции. Проверка записей в production — NOT RUN.

### I-02 · P2 · Задача-зеркало блокируется без удобного перехода из старой формы

Место: `prisma/migrations/20261102100000_booking_commands/migration.sql`,
`booking_managed_task_guard_fn`. Guard защищает все существующие task writers,
но старые generic task routes могут показать общую ошибку вместо ссылки на
встречу. Основной сценарий через `/meetings` доступен. Рекомендуется `/clarify`:
отдельная понятная ошибка «Откройте встречу» и ссылка для generic task UI.
Снимать DB guard ради удобного текста нельзя.

### I-03 · P2 · Пропускная способность worker задана консервативно

Место: `src/lib/booking/effect-worker.ts`, `runBookingEffectWorker`.
Тик обрабатывает не более 10 активных организаций, 20 intents на организацию
и 45 секунд работы, с сохранённым курсором. Сотни одновременно активных tenants
или массовая загрузка создадут очередь. Профиль реальной нагрузки отсутствует.
Рекомендуется `/optimize`: выбирать tenants с due work, отдельно планировать
secret cleanup, измерить lag и затем выбирать лимиты. Лимиты не заменяют SLA.
Для встречи задержка проекции не задерживает появление в журнале.

### I-04 · P3 · Месяц в нативном picker зависит от языка браузера

Место: `BookingWorkspace`, input type=month. Даты списка и календаря локализованы
приложением, но нативный month picker может показывать системный язык (это видно
в fixture Chromium с English locale). Рекомендуется `/polish`: локализованная
видимая подпись месяца при сохранении доступного нативного выбора.

### I-05 · P1 · Cutover и rollback требуют отдельной release-подготовки

Deferred guard намеренно отвергает старый writer без event/head. Поэтому после
миграции старый процесс не должен продолжать принимать новые записи, а возврат
на предыдущий main не является совместимым откатом записи: тот код не знает
новые команды и статусы. Это подтверждается direct-writer PostgreSQL-сценарием,
а не предположением о неизвестном сервере.

До выпуска необходимы совместимый rollback artifact, короткое закрытие/дренирование
старых write-запросов и проверенный порядок включения новых команд. Старые формы
в открытых браузерах должны обновиться. Текущий PR не выдаёт обычный auto-rollback
на старый main за готовый протокол этого cutover. Снимать DB guard или удалять
новые данные для отката нельзя. **Production release: NO-GO до закрытия I-01/I-05.**
Работа над интерфейсом/кодом и допуск к production — разные результаты аудита.

## Положительные свойства, которые нужно сохранить

- Coordinator grant не выводится из текстового department или общего manager role.
- Публичные URL сохранены; capability не попадает в служебные DTO и event payload.
- Главный статус встречи не зависит от готовности Google/Task/Lead.
- CAS, одинаковый порядок блокировок и старые/новые buffers применяются сервером.
- Legacy import не выдаётся за исходное создание; неоднозначные отсутствующие
  CRM-связи не дублируются автоматически.
- Неопределённая внешняя доставка видна как требующая сверки; она не называется
  успешно доставленной и не повторяется вслепую.
- Follow-up остаётся обычной задачей с существующими обязательными полями.
