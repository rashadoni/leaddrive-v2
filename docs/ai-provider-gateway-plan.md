# ИИ-провайдеры: один вход, свой ключ у каждой организации

Задание владельца, 2026-11-09: «для каждого тенанта свой API, чтоб клиент сам
определял трату; сюда входит всё — звонки, ассистент, переписка»; «если сейчас
хаос или хардкод — исправить, чтоб было чётко, с одного входа и выхода».

## Что сейчас (замер по коду 2026-11-09)

- **Ключ один на всю установку.** Claude, Gemini, OpenAI, Voyage, Google Vision —
  ключ из окружения сервера; распознавание речи линии (Chirp) — файл на сервере;
  станция АТС — свой ключ Gemini и Vertex у себя. Ключа организации нет ни у
  одного ИИ-провайдера. Исключения — Apify (свой токен организации, иначе
  платформенный) и SMS (Twilio/Vonage).
- **Вызовы разбросаны.** 46 файлов сами создают клиент Claude, 36 мест читают
  ключи прямо из `process.env`, 86 раз модель вписана строкой в код
  (`claude-haiku-4-5-20251001` — 62 раза).
- **Трата видна наполовину.** Дневной бюджет организации ($5 по умолчанию,
  `checkAiBudget`) считает только Claude и Voyage. Gemini, OpenAI, Chirp, Vision,
  Vertex не считаются нигде. Чат Da Vinci, анализ сделок, тикеты, портал,
  квалификация лидов бюджет не проверяют вовсе.
- **Мёртвые заготовки.** `TenantProviderEntitlement.billingMode = byok` пишется
  при создании организации и нигде не читается; комментарий в
  `anthropic-client.ts` обещает ключ организации из ChannelConfig — его никто не
  передаёт; ошибка чата отправляет «в Настройки → Интеграции», где поля для
  ключа нет.

## Как будет

**Один вход.** Все вызовы ИИ идут через один модуль — `src/lib/ai/gateway/`:

    const ai = await aiFor(orgId, "davinci-chat")   // организация + функция
    ai.anthropic.messages.create(...)                // как раньше

Модуль за один раз:
1. **Берёт ключ.** Свой ключ организации, если она его ввела; иначе ключ
   платформы, если организации это разрешено; иначе — понятный отказ «ИИ не
   подключён» (без падения).
2. **Проверяет бюджет** организации до вызова (только когда платит платформа:
   со своим ключом клиент ограничивает трату у провайдера сам).
3. **Записывает трату** после вызова в один журнал `ai_usage`: организация,
   функция, провайдер, модель, токены/секунды, $ и чей ключ. По нему —
   бюджет, отчёт клиенту и наш счёт.
4. **Знает модели и цены** — одна таблица для всех провайдеров; в коде модели
   строкой больше нет.

**Хранение ключей.** Таблица `tenant_ai_credentials` (организация, провайдер,
ключ), FORCE RLS, ключ зашифрован ключом данных организации
(`tenant-data-keys`). Наружу — только маска `sk-ant-…a1b2`. При сохранении —
проверочный бесплатный запрос к провайдеру (список моделей).

**Кто платит без своего ключа** (владелец, 2026-11-09: «решаю по каждому
клиенту»): у организации одна галочка «ИИ на нашем ключе» — ставит только
суперадмин платформы в карточке клиента. У текущих клиентов включена, чтобы
ничего не остановилось. Выключена и своего ключа нет — ИИ этого провайдера у
клиента не работает, с понятным сообщением.

**Где настраивать и смотреть.** «Настройки → ИИ и расходы» (только админ
организации): по каждому провайдеру — ключ и его состояние, дневной лимит.
**Отчёт по затратам** (владелец, 2026-11-09: «по каждому сервису из каждого
агента»): за выбранный период — сколько потратил каждый провайдер, каждая
функция (чат, звонки, переписка, соцсети) и каждый ИИ-агент, и чей ключ.
Источник один — журнал `ai_usage` (в строке есть `agentId`). Разрез по времени —
**по дням, неделям и месяцам** (владелец: «в красивой форме»): переключатель
«день / неделя / месяц», график трат по периодам, под ним таблица — провайдер,
функция, агент, сумма, чей ключ. Макет — владельцу до кода.

**Сторож.** Тест-гейт запрещает создавать клиент провайдера и читать ключ из
окружения вне `gateway/` — хаос не вернётся.

## Этапы (каждый — свой PR)

1. **Ядро + Claude.** `gateway/`, `tenant_ai_credentials`, `ai_usage`, таблица
   цен; все 46 мест Claude — через вход; бюджет проверяется везде, включая чат.
2. **Страница «ИИ и расходы»** (`/settings/ai-spend`, макет одобрен
   2026-11-10: «Давай») — ключи, лимит и отчёт по дням/неделям/месяцам с
   графиком и выгрузкой в Excel. Видит только админ организации. Решения,
   принятые вместе с макетом:
   - **Лимит один и у одного хозяина — у клиента** (владелец 2026-11-11:
     «зачем ты ставишь лимит? лимит в балансе сколько загрузил… если клиент
     захочет, то пусть ставит лимит»; отменяет решение 2026-11-10, где лимит
     ставил суперадмин). Навязанного лимита нет: без записанного
     `aiDailyBudgetUsd` ИИ не останавливается (`readDailyAiLimit` в
     `src/lib/ai/budget.ts`; до 2026-11-11 было $5 в день, а включение набора
     Advisor писало $10). Админ организации ставит и снимает лимит на этой
     странице (PATCH `/api/v1/settings/ai-budget`, `limit` от $0,5 до $10 000
     или `null`); остальные сотрудники — нет. В карточке клиента у
     суперадмина поля больше нет — у одной цифры был бы второй хозяин.
   - **Со своим ключом лимита LeadDrive нет**: `checkAiBudget` считает только
     `keySource = platform`, вход не проверяет бюджет на ключе организации.
   - **Свой ключ — только у провайдеров, чьи вызовы все идут через вход**
     (`SELF_KEY_PROVIDERS`, сейчас один Claude). Остальные строки на странице
     говорят «Свой ключ — позже»: ключ, введённый для Gemini до этапа 3, лежал
     бы неиспользованным. Ключ проверяется бесплатным запросом (список
     моделей) и не сохраняется, если провайдер его не принял.
   - Подписи функций — в `gateway/features.ts` на трёх языках, их читают и
     страница, и Excel.
3. **Gemini, OpenAI, Voyage, Vision, Chirp** — через вход и в журнал
   (владелец 2026-11-10: «Да, этап 3»). Вход для провайдеров без SDK —
   `aiKeyFor(orgId, provider, feature)` (`gateway/access.ts`): ключ, лимит на
   ключе платформы и `journal(...)` после ответа. Ключи платформы читает
   только `gateway/platform-key.ts`, сторож `ai-gateway-single-entry.test.ts`.
   - Voyage (база знаний, договоры) — одна функция `voyageEmbedding` вместо
     трёх копий, токены из ответа Voyage.
   - OpenAI: расшифровка звонков, голосовых из Instagram/TikTok, соцмониторинга
     — по длине звука; разбор после звонка — по токенам ответа.
   - Google Vision (текст на фото соцмониторинга) — за снимок.
   - Gemini: восстановление заказа линии из расшифровки — по токенам;
     голосовой ассистент — ключ организации для токена сессии, трата пишется
     при закрытии сессии по токенам Google: консоль складывает `usageMetadata`
     каждого хода (`src/lib/ai/voice/live-usage.ts`) и отдаёт их серверу,
     сервер считает по таблице Live (как линия Зейтуна), не ниже входящего
     звука за оплаченные секунды. Без токенов (вкладку закрыли, сессию добил
     крон) — оценка по минутам. Владелец 2026-11-10 «Да, сделай» после живой
     проверки, где минутная оценка оказалась заниженной; озвучка ассистента
     (Vertex) — по длине речи, ключ всегда платформы.
   - Chirp (второе ухо линии) — только журнал, на сервисном аккаунте
     платформы; лимит его не останавливает, чтобы линия не глохла посреди звонка.
   - Свой ключ открыт для Claude, Gemini, OpenAI, Voyage и Google Vision;
     каждый проверяется пробным запросом (у Voyage — одно слово).
   - Цены — `gateway/pricing.ts`, из сторонних сводок цен на 2026-11-10
     (страницы Google и OpenAI тогда не открылись): Gemini 3.8 Flash
     $0,75/$3,75 до конца 2026, GPT-5.6 Luna $0,20/$1,20, Whisper $0,006/мин,
     Chirp $0,016/мин, Vision $0,0015/снимок, Gemini Live ≈ $0,0225/мин.
   - Демо для проспектов (`gemini-speech.ts`) и проверка провайдера кроном —
     ключ платформы, не организации, в журнал не пишутся.
4. **Станция АТС.**
   - **Сделано — трата линии в журнале** (владелец 2026-11-11: «почему расходов
     0?»; у Зейтуна в отчёте был ноль, хотя линия — самая дорогая его часть).
     Ядро станции кладёт в итог звонка (`call-result`) поле `usage`: токены
     Gemini Live за плечо ИИ (сумма `usageMetadata` по модальностям — тот же
     счёт, что строка `zeytun_cost` в журнале станции) и озвучку (запросы,
     знаки, секунды вернувшегося звука). CRM пишет их в `ai_usage` организации
     линии, функция `phone-line`, ключ платформы
     (`src/lib/voice-agent/pharmacy/zeytun-line-spend.ts`), один раз на плечо:
     повтор того же итога (станция переспрашивает при сбое) не пишется, второе
     плечо после неотвеченного перевода — пишется. Ядро без `usage` — оценка
     Live по длине плеча, $0,13/мин (`UNIT_PRICING.phoneLineLiveMinute`: четыре
     звонка стенда давали $0,08–0,24/мин, растёт с длиной звонка — каждый ход
     заново оплачивает весь промпт и каталог); озвучка тогда не считается.
     Порядок выкатки — сначала CRM (схема строгая), потом ядро станции.
     Трата линии входит в дневной лимит организации, если та его поставила,
     как Chirp: саму линию лимит не останавливает, а Da Vinci, голос и
     восстановление заказа — да.
   - **Не сделано — ключ.** Станция перестаёт держать свой ключ: на начале
     звонка CRM выдаёт ей одноразовый токен Gemini Live от ключа организации
     (так уже работает голосовой ассистент в браузере). Нужна установка на
     станцию — с паролем владельца, предупредить заранее.
   - Исходящие ИИ-звонки станции (агент Gobustone, обратный звонок по листу
     ожидания) в журнал Live пока не пишутся: у них свой путь итога.
5. **Соцмониторинг.** Токены Apify/Bright Data/X — в то же хранилище и журнал.

Деньги провайдеров, которые не ИИ (WhatsApp/Meta, SMS, телефония), — вне этого
плана: у них уже свои подключения организации.

## Хвосты, замеченные по ходу

- `scripts/reset-brandprotection-scenario-monitoring.mjs` переносит дневную
  трату ИИ соцмониторинга через сброс, считая её по `ai_interaction_logs`.
  Бюджет с 2026-11-09 считает `ai_usage`, которую сброс не трогает: в день
  сброса перенос посчитает эти траты второй раз. Перед следующим сбросом —
  считать перенос по `ai_usage` или не переносить вовсе.
