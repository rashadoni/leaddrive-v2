# Зейтун: метод 1С со списком сотрудников

Задание для программиста 1С Зейтуна. Дата: 2026-11-05. Макет экрана, ради которого
нужен метод, владелец одобрил («Давай»): `docs/mtm-attendance/mockups/employee-import/`.

## Зачем

Зейтун ведёт учёт рабочего дня в LeadDrive (приложение Time): сотрудник
отмечает приход и уход телефоном. Сотрудников около 1000, и вводить их в
LeadDrive вручную — день работы кадровика и тысяча опечаток. Нужно, чтобы
LeadDrive брал список сотрудников из 1С и каждую ночь забирал изменения:
принятых, переведённых, уволенных.

LeadDrive **только читает**: в 1С ничего не пишет и ничего не меняет.

## Вопрос до начала работы

В какой базе ведутся кадры? Если это отдельная база (например, «Зарплата и
управление персоналом»), а не та, где опубликован `ZTNMOBILE` и
`AvailableBalances`, — метод нужен в кадровой базе, со своим адресом и
логином. Сообщите, пожалуйста, какой вариант.

## Метод: список сотрудников

Предлагаем HTTP-сервис, как `AvailableBalances`: вход Basic, JSON, `GET`.
Название, например, `ListEmployees`. Пользователь — отдельный, только на
чтение этого метода.

Ответ — все сотрудники, принятые на работу хотя бы раз, **включая уволенных
за последние 90 дней** (чтобы LeadDrive увидел увольнение):

```json
{
  "Дата": "20261105030000",
  "Сотрудники": [
    {
      "GUID": "guid-сотрудника",
      "ТабельныйНомер": "00-000123",
      "ФИО": "Məmmədov Rauf Əli oğlu",
      "Телефон": "+994504441212",
      "Должность": "Baş mütəxəssis",
      "Подразделение": { "GUID": "guid-подразделения", "Наименование": "Logistika" },
      "ПодразделениеРодитель": { "GUID": "guid-департамента", "Наименование": "Kommersiya departamenti" },
      "Руководитель": "guid-сотрудника-руководителя",
      "МестоРаботы": "Beqok Biznes Mərkəzi",
      "ДатаПриема": "20240115",
      "ДатаУвольнения": null
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `GUID` | да | Постоянный идентификатор сотрудника в 1С. **По нему LeadDrive узнаёт человека** при каждом следующем запросе — он не должен меняться при переводе или смене ФИО |
| `ТабельныйНомер` | нет | Только для сверки и поиска; в LeadDrive свой номер |
| `ФИО` | да | Как в кадровых документах |
| `Телефон` | да | Мобильный с WhatsApp, в формате `+994…`. По нему человек входит в приложение: на этот номер приходит код. Без телефона сотрудник не добавляется, LeadDrive покажет его кадровику как ошибку |
| `Должность` | нет | Название должности |
| `Подразделение` | нет | Отдел, где работает сотрудник |
| `ПодразделениеРодитель` | нет | Департамент над отделом, если он есть |
| `Руководитель` | нет | `GUID` непосредственного руководителя из этого же списка |
| `МестоРаботы` | нет | Офис или склад, где сотрудник отмечается, если 1С это знает. Название должно совпадать с филиалом в LeadDrive; если не знает — кадровик укажет филиал сам |
| `ДатаПриема` | да | `ГГГГММДД` |
| `ДатаУвольнения` | нет | `ГГГГММДД` или `null`. Последний рабочий день |

Если сотрудник работает на двух должностях (совместительство), нужна одна
строка — основная работа.

## Как LeadDrive это использует

- **Первый раз** — кадровик в LeadDrive нажимает «Получить список из 1С»,
  видит, сколько людей добавится и какие строки с ошибками (нет телефона, один
  телефон у двоих), и подтверждает.
- **Каждую ночь** (около 03:00 по Баку) — один запрос. Принятые добавляются,
  перевод и смена должности обновляются. Увольнение LeadDrive сам не делает:
  оно ждёт подтверждения кадровика.
- ФИО, должность, отдел, руководитель и даты в LeadDrive у таких сотрудников
  не правятся — правка в 1С, LeadDrive заберёт её ночью.

## Объём и нагрузка

Около 1000 строк, раз в сутки и по кнопке кадровика. Если удобнее отдавать
частями, добавьте параметры `Страница` и `РазмерСтраницы` и поле
`ЕстьЕщё` в ответе.

экран проверки до того, как включить ночное обновление.
