# Синхронизация календарей: Google и Microsoft Outlook

Одно окно: встречи CRM и встречи, назначенные в личном календаре, видны на
одной шкале дня в разделе «Встречи», и ни одна из них не отдаётся клиенту как
свободное время.

Работает в обе стороны и у каждого сотрудника по отдельности — календарь
подключает сам человек в «Настройки → Интеграции», своей кнопкой:

- **оттуда сюда.** Занятые часы подключённого календаря вычитаются из
  свободного времени на публичной странице записи, в WhatsApp-агенте и при
  переносе встречи. На дневной шкале они стоят серым блоком. У кого Google и
  Outlook подключены оба — считаются оба.
- **отсюда туда.** Каждая подтверждённая будущая встреча CRM попадает в
  каждый подключённый календарь хоста, меняется вместе с переносом и
  удаляется при отмене.

## Что видно и кому

Название чужой встречи — личные данные человека, чей это календарь. Поэтому:

- свой календарь сотрудник видит с названиями («Dişçi, 15:00»);
- администратор и координатор видят, что час занят, и каким календарём, но
  **не** название. Ровно столько, сколько серый блок говорил и раньше.

Поменять это правило — одна строка в `src/app/api/v1/bookings/external-events/route.ts`
(`ownCalendar`), и это решение владельца, а не настройка.

## Что нужно один раз: приложение в Microsoft

Google-приложение у CRM уже есть (`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`).
Для Outlook нужно зарегистрировать своё — это делает владелец, в портале Azure:

1. **Microsoft Entra ID → App registrations → New registration.**
   Поддерживаемые типы аккаунтов — «Accounts in any organizational directory
   and personal Microsoft accounts», если календари будут из разных компаний.
2. **Redirect URI** (тип Web):
   `https://app.leaddrivecrm.org/api/v1/integrations/outlook-calendar/callback`
3. **API permissions → Microsoft Graph → Delegated:** `Calendars.ReadWrite`
   и `offline_access`. Больше ничего не нужно: CRM не читает почту и не
   смотрит чужие календари.
4. **Certificates & secrets → New client secret**, скопировать значение.
5. Положить в окружение прода (`/etc/leaddrive/app.env`, через рабочий процесс
   прод-переменных, см. `docs/DELIVERY-ARCHITECTURE.md`):
   `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`,
   `MICROSOFT_TENANT_ID` (`common`, либо id одной компании).

Пока их нет, карточка «Microsoft Outlook» в интеграциях так и говорит, а её
кнопка выключена — никто не уходит к Microsoft за отказом.

## Как это устроено в коде

| Что | Где |
| --- | --- |
| Какие календари подключены (по одному на провайдера) | `src/lib/calendar/accounts.ts` |
| Чтение: занятость и события с названиями | `src/lib/calendar/events.ts` |
| Microsoft Graph на `fetch`, без SDK | `src/lib/calendar/microsoft.ts` |
| Подключение и отключение, общее для обоих | `src/lib/calendar/connection.ts` |
| Запись встречи CRM в календари | `src/lib/booking/integration-intents.ts`, `src/lib/booking/effect-worker.ts` |
| День глазами календаря сотрудника | `src/app/api/v1/bookings/external-events/route.ts` |

Три вещи, которые легко сломать:

- **Непрочитанный календарь — не пустой календарь.** Любая неполная выдача
  (таймаут, страница с ошибкой, чужой часовой пояс в ответе Graph) бросает
  ошибку, и хост на это время выпадает из дня целиком. Вернуть «что успели» —
  значит продать занятый час.
- **Набор календарей проверяется ещё раз под замком хоста**
  (`connectedCalendarKey`): подключение или отключение календаря между
  расчётом свободного времени и записью даёт `AVAILABILITY_CHANGED`, а не
  встречу поверх непрочитанного часа.
- **Graph сам выдаёт id события**, в отличие от Google. Поэтому создание
  несёт `transactionId` (это `generation` привязки), и повтор после
  потерянного ответа сначала спрашивает Microsoft, не создано ли уже —
  иначе в календаре мастера оказались бы две одинаковые встречи.
