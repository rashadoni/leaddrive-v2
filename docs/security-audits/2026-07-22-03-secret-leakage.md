# Security audit #3 — утечки ключей и секретов

Дата: 2026-07-22  
Режим: read-only, без изменений и без вывода значений секретов

## Итог

В текущем tracked-коде не подтверждена утечка действующего API-ключа, приватного ключа, токена платежей или credentials в frontend/public-артефакты. Локальный `.env` существует, но игнорируется Git и не отслеживается.

Обнаружены два риска конфигурации и хранения документации, которые нужно исправить отдельно.

## Findings

### SEC-03-1 — предсказуемые webhook verify tokens в `.env.example`

Severity: P2 (конфигурационный риск; production exposure не подтверждён)

`.env.example` содержит фиксированные значения для `WHATSAPP_VERIFY_TOKEN` и `INSTAGRAM_WEBHOOK_VERIFY_TOKEN`. Это не действующие значения по доказательствам аудита, но копирование примера в production создаст предсказуемый токен.

Рекомендация: оставить пустые значения или явный placeholder, добавить startup-проверку, запрещающую известные/default значения.

### SEC-03-2 — старые отчёты содержат fallback-secret и эксплуатационные детали

Severity: P2 (утечка внутренней security-информации; действующий production secret не подтверждён)

Tracked-файл `deliverables/auth_analysis_deliverable.md` содержит строку `portal-secret` как описание старого fallback JWT-ключа, а также старые сведения о development `.env`. Это не credential production по текущей проверке, но публикация репозитория раскрывает детали, которые не должны находиться в общем доступе.

Рекомендация: удалить/заредактировать секретоподобные значения в tracked-отчётах, проверить Git history и при подтверждении реального использования ротировать соответствующий secret.

## Что проверено

- tracked-файлы и имена `.env`/credential-файлов;
- regex-поиск известных форматов Stripe, Google, GitHub, Slack, AWS и PEM-ключей;
- публичные файлы и `public/data/**`;
- client-компоненты на использование non-`NEXT_PUBLIC_` env;
- Git history по известным secret-паттернам.

Результат: действующий секрет в текущем frontend/public bundle не найден; `public/data` содержит только справочные названия компаний и pricing-данные без credential-полей.

## Следующий шаг после разрешения

1. Убрать default webhook tokens из примеров и добавить защиту от default values.
2. Заредактировать старые tracked security-документы и проверить историю на реальные утечки.
3. Проверить production environment names/lengths без вывода значений и при необходимости ротировать секреты.
4. Запустить targeted tests и подготовить remediation report.

До отдельного разрешения эти изменения не выполнялись.
