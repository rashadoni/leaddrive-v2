Хочу сделать интерактивные видео-гайды для этого проекта — по одному короткому видео на каждую вкладку/раздел, на 3 языках (az/en/ru), с озвучкой. Рабочий эталон уже отлажен в соседнем проекте — **портируй оттуда конвейер, не изобретай заново**.

**Сначала прочитай эталон** (в соседнем репозитории `~/Projects/leaddrive-v2`):
- `scripts/produce-guides.mjs` — рекордер (Playwright recordVideo 1280×720 + ffmpeg mux озвучки, логин по API `/api/auth/csrf` + `/api/auth/callback/credentials`, видимый курсор).
- `video/scenarios/overrides.mjs` — рукописные сценарии (тут вся суть); посмотри готовые `social-monitoring-*` и `products` как образец.
- `src/components/help/help-button.tsx`, `help-drawer.tsx`, `src/content/help/video-assets.ts` — паттерн `videoSlug` (видео под активную вкладку).

**Озвучка (точно так):** az → Google Gemini, модель `gemini-2.5-flash-preview-tts`, голос `Kore` (суточный лимит ~100/день, поэтому Gemini только для az; ключ `GEMINI_API_KEY`). en/ru → Azure Speech `en-US-JennyNeural` / `ru-RU-DmitryNeural` (быстро, без лимита; `AZURE_SPEECH_KEY`/`AZURE_SPEECH_REGION`). Это согласованная облачная TTS — локального фолбэка не делать.

**Модель озвучки и 17 ноября 2026.** `gemini-2.5-flash-preview-tts` Google отключает не раньше 2026-11-17. До тех пор всё читается ею, как и раньше. Когда она перестанет отвечать, `produce-guides.mjs` и `tts-voice-samples.mjs` сами перейдут на `gemini-3.8-flash-tts` и напишут об этом в лог; выбрать модель заранее можно через `GEMINI_TTS_MODEL` (`gemini-3.8-flash-lite-tts` на реальных фразах читает в темпе нынешних записей, `gemini-3.8-flash-tts` — примерно на 15–20% медленнее; на слух их не сравнивал никто). Запрос у моделей разный, и просто подставить новое имя в старый запрос нельзя: 3.8 читает текст запроса дословно и отдаёт WAV. Различие целиком в `scripts/lib/gemini-tts.mjs` — запросы к Gemini TTS собирать только через него. Говорящий гид демо (`scripts/demo-guide/generate-voice.ts`) сам на новую модель не переходит: запись названа по модели, которая её читала, поэтому смена модели — это перезапись всех фраз разом, решением, а не тихо.

**Критичные правила (не нарушать):**
1. **Тайминг — `holdUntil(доля)`, не фиксированные `sleep`.** Сцена держится `max(действия, озвучка)`; az почти вдвое длиннее en/ru → фиксированные паузы под az дают хвостовую тишину на en/ru. Задавай биты как доли озвучки: `await h.<action>(); await h.holdUntil(0.35); …`, последний бит ≤0.92.
2. **Селекторы проверять живьём** (мини-probe: логин→перейти→убедиться, что элемент есть и кликается) ДО записи. Диалоги открывать надёжно: клик → poll реального маркера открытия (крестик диалога) → до 3 ретраев.
3. **Планка качества:** озвучка длинная и содержательная; курсор ведёт по РЕАЛЬНЫМ фичам (открыть форму, ввести данные, кликнуть подвкладку), не декоративно; что говоришь — то и показывай. Формы: открыл → `Отмена`/`×`, ничего не сохраняем.
4. **Верификация каждого видео обязательна:** `ffmpeg … silencedetect=noise=-40dB:d=2.5` → 0 пауз; извлеки кадры середин сцен и САМ посмотри, что вкладка активна и действие сработало. Не угадывай.
5. Запись против демо-тенанта с `ALLOW_MUTATIONS=1` (на проде клики сами становятся hover). Выкладка видео + инвалидация CDN — только с моего разрешения.
6. **Никаких безлимитных автономных `/loop` на дорогой модели.** Рутину — на Sonnet, следи за расходом.

**Порядок работы:** разберись в структуре проекта (стек, роутинг, где кнопка помощи, где .env с ключами TTS, есть ли демо-стенд) → перечисли вкладки первого раздела → по одной: напиши сценарий (3 языка) → запиши az → проверь кадры/тишину → почини → запиши en/ru → покажи мне. Раздел за разделом.

Начни с изучения проекта и эталона, потом покажи план по первому разделу и **спроси, если что-то неясно**, прежде чем записывать.
