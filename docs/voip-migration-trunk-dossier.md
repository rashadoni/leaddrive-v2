## 3. Формат номера — активный баг CRM

Правило пропускает наружу **только `0XXXXXXXXX`**: начинается с `0`, ровно 10 цифр.
Национальный азербайджанский формат.

CRM же передаёт номер как есть из карточки контакта — в E.164:

```
+994512060838   ← что шлёт CRM: не начинается с 0, длина не 10 → правило не совпадает
0512060838      ← что ждёт АТС: 10 цифр, начинается с 0
```

Преобразование: `+994` + 9 цифр → `0` + те же 9 цифр.

```
+994512060838 → отбросить "+994" → 512060838 → добавить "0" → 0512060838 ✅
```

Это отдельная от «нет устройства» проблема: даже с зарегистрированным
телефоном звонок на `+994...` не уйдёт. Чинить в исходящем тракте
(нормализация номера перед `makecall`), а не в правилах АТС —
на своей АТС правило будет своё, но нормализация номера всё равно нужна.

В коде уже есть родственный хелпер `threeCxPhoneVariants`
(`src/lib/voip/threecx-crm.ts`) — он решает ту же задачу `0XX ↔ +994XX`,
но только для поиска контакта по входящему номеру. Для набора аналога нет.
