# Единая иерархия кнопок CRM

## Поручение и результат

Пользователь одобрил почти чёрные главные кнопки с белым текстом в светлой
CRM и попросил внедрить общее правило, чтобы ему не приходилось находить
пропуски по разделам. Утверждены светлый фон и белые карточки. Новые тёмные
фоны не вводятся; совместимость кнопок с уже существующими режимами и
отдельными инверсными панелями сохраняет читаемость.
Вторичные действия спокойные, выбранные фильтры и вкладки не выглядят как
главные действия. Оранжевый остаётся фирменным акцентом. Существующие белые
карточки, рамки и смысловые цвета статусов сохраняются.

## Последовательность

1. Инвентаризация всех страниц `(dashboard)` и используемых UI-компонентов:
   общий Button, обычные button/a, условные варианты фильтров, CSS, окна и
   порталы, dashboard с обоями. Зафиксировать исключения по смыслу, не по
   названию раздела. Не путать просмотр исходников с проверкой браузером.
2. Общие токены пары фон/текст и hover для светлой, тёмной и force-light
   поверхностей. Подключить общий Button и нативные главные действия.
3. Сделать «Все приложения» вторичной кнопкой. Отделить выбранные фильтры и
   переключатели от primary через общий вариант; исключить оранжевые
   локальные переопределения обычных действий. Не менять поведение/права.
4. Проверить CSS-конфликты, контраст и состояния hover/focus/disabled/loading;
   проверить формы/порталы, ссылки-кнопки, тёмную тему, обои и узкий экран.
5. Автоматический контроль исходников против возвращения локальных обычных
   оранжевых CTA и использования primary для выбранных фильтров. Проверять
   смысловые исключения явно; не перекрашивать статусы/данные wildcard CSS.
6. Targeted проверки последовательно на Contabo; полный typecheck/build и
   более широкие проверки — hosted CI. Выпуск через PR → проверенный main →
   GitHub Actions → точный artifact SHA / ping / визуальная проверка.

## Критерии завершения

- Правило находится в общих компонентах/токенах и действует во всех разделах,
  включая диалоги; нет отдельной реализации для «Компаний» или «Сделок».
- В обычных действиях нет необъяснённых локальных оранжевых заливок.
- У primary читаемый контраст фон/текст во всех поддерживаемых темах.
- Навигация/выбор фильтра не используют стиль главной кнопки.
- Цвета разрушительных действий, телефонии, статусов и провайдеров не
  изменены случайно. Публичные сайты и печатные документы вне CRM scope.
- Отчёт отдельно называет исходники, реально просмотренные страницы,
  состояния и ограничения доступа/данных. Непроверенное не считается PASS.
- Ветка сохранена checkpoint-коммитами; опубликованный результат считается
  опубликованным только после успешных проверок и production smoke.

### Уточнение до выпуска

Пользователь потребовал сначала показать палитру на его фактической светлой
CRM. Тёмные варианты из предложения исключены. Сейчас только light preview;
публикация остановлена до согласования. Черновой dark/inverse код из более
ранней интерпретации не является одобренным результатом; перед продолжением
пересмотреть его согласно этому уточнению.


### Согласование и продолжение — 26 октября, Asia/Baku

После просмотра палитры и временного preview на реальных Companies/Deals
пользователь ответил «отлично». Пауза до согласования завершена. Принят
светлый вид: primary #171717 / белый текст, hover #2E2E2E, outline secondary,
серый выбранный фильтр. Проверка dark/force-light/inverse — только совместимость
с уже существующими поверхностями, не предложение новых тёмных фонов.


### Проверка опубликованной версии и завершение исключений

PR #1074 опубликован; артефакт и ping подтверждены на трёх доменах.
При просмотре живой CRM обнаружены старые прямые стили выбора в поддержке
и MTM. Они переводятся на общий вариант отдельным продолжением, поэтому
задача пока не закрыта. Общие главные кнопки и окна уже проверены на проде.
