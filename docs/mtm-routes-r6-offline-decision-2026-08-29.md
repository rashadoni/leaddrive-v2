# MTM Routes R6 — решение по офлайн-горизонту

**Дата:** 2026-08-29
**Основание:** 2026-08-29 владелец поручил выбрать консервативную лучшую
практику для офлайн-горизонта.

Для будущего Route sync v2 устройство получает маршруты на семь локальных
календарных дней, включая текущий день: интервал `[today, today + 7 days)`.
Граница считается в timezone tenant.

Это решение ограничивает только будущий snapshot маршрутов. Оно не разрешает
удалять бизнес-записи на сервере.

**История маршрутов на устройстве:** по консервативной практике завершённый
или отменённый маршрут не остаётся за пределами недельного окна
(`terminalHistoryDays: 0`). Будущий v2-клиент может удалить cache-запись только
после успешной синхронизации и только если с маршрутом не связана
несинхронизированная операция. Серверная запись и audit в любом случае не
удаляются. Текущий v1 cache этим контрактом не очищается.

До transactional change journal не включаются cohort rollout и новый endpoint.
