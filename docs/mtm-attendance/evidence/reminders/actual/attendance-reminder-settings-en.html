How agents work: visits, routes, alerts.

Building routes

Several agents on one route
A route can have a main agent and helpers.
Show travel time
Travel time between route stops is shown using Google Maps. It works only if Google Maps is connected for your company; otherwise no time is shown.
Link to directions in Google Maps
The next stop gets a link that opens directions in Google Maps. It does not change the order of stops.
No routes on days off
A route cannot be planned on a day the work calendar marks as a day off.

An agent who has not started the route by this hour is marked “Late” on the map. No alert is created. Online agents only.

How long to wait for the phone's signal
If an agent's phone has not sent its position for longer than this, the map shows them as offline.

Link to an agent's location
Like a taxi app: a manager sends a link from the agent's card on the map, and the person sees where the agent is now, without signing in. Only during the workday, with no history and no route. The agent is not notified. If you switch it off, every link handed out stops working for good.

Modules

Clients (doctors, pharmacists, etc.)
When off, the section disappears from the menu and the agent app. No data is deleted.
Pharmacy promotions
When off, hidden from the menu and the agent app; no data is deleted.
Workday attendance
Off by default. Enables work-time reports in MTM; user permissions control access to the data.
Reject attendance marks outside a branch
Off by default: these marks are accepted and flagged. When enabled, only marks confirmed to be outside a branch are rejected. Time is accepted without consent or GPS, with an uncertain location, and from older app versions.

Agents in the app

Agents create their own tasks
An agent can create and manage their own tasks in the app.
Own tasks can repeat
An agent can make their own task repeat.
Agents see their team's meetings
An agent sees who on their team meets which client, when and where. Colleagues' phones, notes and current location are never shown.

Attendance reminders

Remind employees
In the app: record arrival after the scheduled start and departure after the scheduled end. Once per day, excluding days off and approved absences.
Notify managers
In notifications: an arrival is still missing after the grace period, or was recorded later than scheduled. Only employees in the manager’s current scope.

Attendance mark checks

Allow a shared phone
Enable this when employees legitimately share a phone. New marks from one app installation by different employees on the same day will not create findings. Existing findings remain in the history.
Reject marks with a mock location
Marks are accepted with a finding by default. When enabled, only an explicit mock location signal causes rejection. Missing GPS, consent or evidence from an older app does not mean the location is mocked.
Time difference threshold
Default: 300 seconds. A difference between phone time and server receipt needs review; lost connectivity may cause it. Delivery more than 15 minutes later is flagged separately. Enter 30 to 86400 seconds.
sec

Rarely changed

Apply visit rules
While off, no rule applies: an agent is shown every action and none is required. The rules themselves are kept.
Brand potential kept per agent
A doctor's potential and coverage for a brand are kept separately for each agent, not as one number per doctor.
Loading data from Excel

Technical GPS history thresholds

They decide how a path and stops are worked out from GPS points. Usually there is no need to change them; only a CRM administrator can.

Expected interval in GPS history (seconds)
The phone sends its position at its own rate (currently every 30 seconds) — this value does not change it. It is only used to detect gaps in GPS history and to judge how fresh a point is.
