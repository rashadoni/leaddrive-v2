## 1. Сначала прочитай эталон (`/home/rashad/projects/leaddrive-v2`)

  Вызов: `node scripts/produce-guides.mjs <BASE_URL> [langs] [sections]`, например `node scripts/produce-guides.mjs https://app.example.org az deals deal-detail`. `FORCE=1` — перезаписать существующие.

  Хелперы `h`: `moveTo / hover / click / fill / sleep / holdUntil`.

## 2. Озвучка (точно так)

- **az → Google Gemini** (Google AI Studio): модель `gemini-2.5-flash-preview-tts`, голос `Kore`, ключ `GEMINI_API_KEY`. Суточный лимит ~100 запросов, поэтому Gemini ТОЛЬКО для az.
- **en/ru → Azure Speech**: `en-US-JennyNeural` / `ru-RU-DmitryNeural`, ключи `AZURE_SPEECH_KEY` / `AZURE_SPEECH_REGION` (быстро, без лимита).
- Это согласованная облачная TTS — локального фолбэка не делать. Проверь, что ключи есть в `.env` и что `.env` реально подхватывается запуском.
- **ffmpeg обязателен** (mux + `silencedetect` + `freezedetect`): `ffmpeg -version`, при отсутствии — `sudo apt-get install -y ffmpeg`.

## 3. Планка качества (ГЛАВНОЕ — не нарушать)

1. **Показывай В ДЕЙСТВИИ, а не рассказывай.** Курсор ведёт по РЕАЛЬНЫМ фичам синхронно с речью: открыть форму, ввести пример значения, переключить подвкладку, навести на реальные цифры/график. Что говоришь — то и в кадре. Никакой «говорящей головы» над статичным экраном.
2. **Каждое видео ≥ 2 минут.** Длина сцены = `max(действия, озвучка)`, az примерно вдвое длиннее en/ru → чтобы даже самый КОРОТКИЙ язык давал ≥ 120 сек, пиши содержательную озвучку en/ru суммарно ~110–130 сек (≈8–12 сцен по 10–14 сек речи). az тогда выйдет ~3–4 мин — это норма.
3. Озвучка объясняет: **что это за раздел, ЗАЧЕМ он нужен, как им пользоваться** — по ходу реальных действий, а не абстрактно.
4. **Реальные данные в кадре.** Если сцена зависит от данных — засей демо-тенант заранее, чтобы в кадре не было пустых состояний. (В эталоне перед записью гайда сделок засеяли MEDDPICC у демо-сделки через `PUT /api/v1/deals/{id}` из `page.evaluate` в уже залогиненной сессии — сделай аналог для своих данных.)
5. Формы: открыл → показал → `Отмена`/`×`. Ничего не сохраняем, ничего не удаляем.

## 4. Критичные правила

1. **Тайминг — `holdUntil(доля)`, не фиксированные `sleep`.** Биты задаются как доли длительности озвучки сцены: `await h.click(SEL); await h.holdUntil(0.35); await h.moveTo(SEL2); await h.holdUntil(0.6); …`, последний бит ≤ 0.9. Фиксированные паузы, подогнанные под az, дают мёртвый хвост на en/ru: все действия отстреливаются за 1–2 сек, а дальше картинка стоит до конца озвучки. Именно это когда-то читалось как «слабо смонтировано».
2. **Селекторы проверять живьём ДО записи** (мини-probe: логин → перейти → убедиться, что элемент есть и кликается). Диалоги открывать надёжно: клик → poll реального маркера открытия (крестик диалога) → до 3 ретраев. Предпочитай языконезависимые якоря (`data-tour-id`, стабильные атрибуты) вместо текста.
   - Локализованный `:text('X')` берёт ПЕРВОЕ совпадение, а подзаголовки страниц часто повторяют подписи KPI — для меток карточек используй `:text-is('X')`.
   - `h.hover()` сразу после `h.moveTo()` по ТОМУ ЖЕ таргету может высидеть свой 6-секундный таймаут и сдвинуть озвучку следующей сцены за пределы удержания → пауза, которую поймает `silencedetect`. Достаточно одного `moveTo`.
3. **Верификация каждого видео обязательна, глазами, а не на веру:**
   - `ffmpeg -i FILE -af silencedetect=noise=-40dB:d=2.5 -f null -` → 0 пауз тишины;
   - `ffmpeg -i FILE -vf freezedetect=n=0.003:d=6 -f null -` → 0 замерших кусков (это и ловит мёртвый монтаж; одной тишины НЕ достаточно);
   - контактный лист кадров `-vf "fps=1/8,tile=5x6"` — посмотри сам, что вкладка активна, навигация сработала, данные видны, help-карточка скрыта.
4. Запись против **демо-тенанта**. На проде клики через generic JSON-путь становятся hover (READONLY), но `do`-сцены кликают РЕАЛЬНО — так и снимается навигация. Поэтому в `do` НЕ кликать сохраняющие/разрушительные кнопки: только навигация и «открыть → отменить».
5. **Прячь help-карточку в записи:** у карточки должен быть атрибут `data-help-video-widget` — рекордер прячет её через `GUIDE_CSS`. Иначе «Видео-инструкция» попадёт ВНУТРЬ гайда.
6. **После записи или удаления файлов обнови манифест доступности:** `npm run help-video:sync` и закоммить результат. Карточка и кнопка помощи показываются ТОЛЬКО для пар slug+локаль, перечисленных в сгенерированном манифесте; тест сверяет манифест с диском и валит CI. Реестр в `video-assets.ts` перечисляет все разделы (покрытие роутов), но не попавшие в манифест рендерят пустоту → 404 и «Video hələ yüklənməyib».
7. **Перед публикацией подними константу версии ассетов** (`HELP_VIDEO_ASSET_VERSION`). Она НЕ бампается автоматически: URL получают `?v=${VERSION}`, и при перезаписи файлов с теми же именами CDN продолжает отдавать старые копии (видно по `cf: HIT` со старым размером). Бамп меняет `?v` → промах кэша → свежие файлы.
8. **Публикация (коммит `video/player/*` → деплой → CDN) — ТОЛЬКО с разрешения владельца.** Записывай локально, покажи, публикуй по «ок».
9. **Языки записывай последовательно, не параллельно.** Падение ffmpeg с «Nothing was written into output file» — это не случайность, а `pthread_create: Resource temporarily unavailable` от слишком большого числа параллельных Chromium/node. Чинится повтором именно упавшей ffmpeg-команды: webm и mp3 сцен остаются в `video/.tmp-guides`.
10. **Никаких безлимитных автономных `/loop` на дорогой модели.** Рутину — на дешёвой модели, следи за расходом.
