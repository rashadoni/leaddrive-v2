# scripts/erp — ход работ по модулям «Склад» и «Бухгалтерия»

Здесь лежит открытая часть учёта работ: какие правила и карточки есть, в каком
порядке они идут и что уже сделано. Текста правил здесь нет — только номер,
короткое название, срез, состояние и хэш текста. Правила процесса и карточки
лежат в закрытой папке на сервере.

- `registry.json` — правила: номер, название, срез, состояние, хэш текста.
- `order.json` — карточки и ворота: номер, название, порядок, номера правил.
- `progress/<номер>.json` — кто взял карточку, какие шаги отмечены, записи ворот.

Имён и слов людей здесь нет. У записи о воротах, принятого свидетельства,
снятого вопроса и снятой занятости в этих файлах — только роль, дата и хэш
записи; кто и что сказал, хранится вне репозитория, и по хэшу это не
восстановить.

## Команды

Запускаются из корня рабочей копии, нужен только `python3`.

| Команда | Что делает |
| --- | --- |
| `python3 scripts/erp/next_card.py` | называет одну карточку — ту, которую брать сейчас |
| `python3 scripts/erp/next_card.py --take erp/<номер>-<slug>` | записывает карточку за веткой |
| `python3 scripts/erp/mark.py step <карточка> <шаг>` | отмечает шаг карточки |
| `python3 scripts/erp/mark.py rule <правило> --run <прогон GitHub>` | ставит «сделано» по отчёту прогона |
| `python3 scripts/erp/mark.py note <карточка> --text "…"` | записка следующей сессии |
| `python3 scripts/erp/status.py` | один экран: срезы, карточки в работе, ворота |

Руками `registry.json` и `progress/` не правят: отметки ставит `mark.py`, а
`check_progress.py` на каждом PR проверяет их заново (джобы `pr-scope` и
`static-checks` в `.github/workflows/pr-checks.yml`). PR, который не трогает
`scripts/erp` и тесты правил, эта проверка не задерживает.

## Копия закрытой папки

Закрытая папка лежит под своим git. Этот git помечен настройкой
`erp.private = true` (её ставит `setup_private.py`): без пометки команды в его
историю ничего не пишут — так закрытое не попадает в чужой репозиторий, если
папку положили не туда.

У папки есть копия — отдельный закрытый репозиторий. Его адреса здесь нет: он
записан в настройках git самой папки, дважды — как `origin` и как `erp.copy`.
Копию называет владелец.

`next_card.py` и `mark.py` сами досылают в копию всё, что записано в историю
папки, и идут в сеть, только когда есть что отправить. Не получилось — команда
не падает (запись уже в истории папки), но печатает «ВНИМАНИЕ: копия закрытой
папки НЕ обновилась» своими словами, без адреса копии, а `status.py`
показывает, на сколько коммитов копия отстала и сколько файлов папки не
записано в историю.

Любое сомнение — отказ, а не отправка. Отправки нет, если:

- `origin` есть, а `erp.copy` не записан, либо это разные адреса, либо у
  `origin` несколько адресов или отдельный адрес отправки;
- адрес копии совпал с любым адресом этого репозитория (он открытый) или адрес
  этого репозитория не удалось прочитать;
- git, в котором лежит закрытая папка, — не её собственный: не помечен,
  рабочая копия кода или чужой репозиторий.

Чужую запись в копии команды не затирают: force-push запрещён. На новом сервере
папку восстанавливают клонированием копии в `~/projects/erp-private`; настроек
git после клонирования нет, поэтому владелец заново помечает git папки
(`git config erp.private true`) и называет копию (`git config erp.copy <адрес>`).
До этого команды ничего не пишут и не отправляют.

## Имя теста

Тест правила лежит в `src/__tests__/erp-*.test.ts` и несёт номер правила
латиницей в названии, целым словом: `it("u3-D-28a: платёж больше долга", …)`.
«Сделано» даёт только статус `passed` в отчёте прогона GitHub; выключенный и
пропущенный тест отметку не даёт. Адрес настоящей базы тест берёт из
`ERP_TEST_DATABASE_URL`.
